# reshop — магазин предметов Dota 2

Двухстраничный статический сайт для продажи предметов Dota 2: каталог с фильтрами и страница «Обо мне». Плюс отдельная админ-панель, из которой можно менять карточки и текст страницы, а затем публиковать изменения прямо в GitHub-репозиторий (и на GitHub Pages).

Сайт не требует сборки, npm и сервера: это обычные HTML, CSS и JavaScript. Внешних CDN тоже нет — шрифты и картинки лежат в `assets/`.

---

## Что внутри

```
index.html            — каталог (главная)
about.html            — страница «Обо мне»
admin.html            — админ-панель (noindex)
404.html              — страница для GitHub Pages
data.json             — опубликованные данные: настройки, «Обо мне», предметы
assets/
  css/base.css        — токены, шрифты, шапка, футер, кнопки
  css/site.css        — hero, каталог, карточки, модалка, «Обо мне»
  css/admin.css       — админ-панель
  js/seed.js          — резервная копия data.json (демо-данные)
  js/core.js          — загрузка данных, localStorage, GitHub API, шапка, тосты
  js/site.js          — фильтры, карточки, модалка, страница «Обо мне»
  js/admin.js         — CRUD предметов, редактирование «Обо мне», настройки
  fonts/              — Unbounded + Inter (кириллица и латиница)
  items/              — изображения предметов (webp)
  img/favicon.svg
```

Две публичные страницы — `index.html` и `about.html`. `admin.html` — служебная, её не нужно показывать покупателям.

## Локальный просмотр

Запустите любой статический сервер из папки проекта:

```bash
python -m http.server 8000
```

и откройте <http://localhost:8000>.

> Важно: не открывайте `index.html` двойным щелчком (`file://`). В этом режиме браузер блокирует `fetch('data.json')` и `crypto.subtle`, поэтому каталог покажет только встроенный демо-набор, а вход в админку не сработает.

## Публикация на GitHub Pages

1. Создайте **публичный** репозиторий на GitHub, например `reshop`.
2. Загрузите в корень репозитория всё содержимое этой папки (кроме `tmp/`, если он есть).
3. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**.
4. Выберите ветку `main` и папку `/ (root)`, нажмите **Save**.
5. Через 30–60 секунд сайт будет доступен по адресу `https://<username>.github.io/<repo>/`.

Файл `.nojekyll` уже добавлен — он отключает обработку Jekyll и не даёт GitHub Pages трогать служебные файлы.

### Подключение админки к репозиторию

1. Откройте `https://<username>.github.io/<repo>/admin.html`.
2. Пароль по умолчанию — `reshop`. Сразу смените его в **Настройки → Доступ**.
3. Создайте токен GitHub:
   - **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**;
   - Repository access: только ваш репозиторий магазина;
   - Permissions → **Contents: Read and write** (Metadata: Read — добавится автоматически).
   - Можно использовать и классический токен с галочкой `repo`, но fine-grained безопаснее.
4. В админке откройте **Настройки → GitHub** и заполните:
   - **Владелец** — ваш логин GitHub;
   - **Репозиторий** — имя репозитория;
   - **Ветка** — `main` (или ваша рабочая ветка);
   - **Путь к данным** — `data.json`;
   - **Personal access token** — вставьте токен.
5. Нажмите **Проверить подключение**. Если всё верно — увидите имя репозитория и ветку.
6. Нажмите **Опубликовать**.

Токен хранится только в `localStorage` вашего браузера и отправляется только на `api.github.com`. В репозиторий и в код сайта он не попадает.

### Публикация кода без ручной загрузки

Кнопка **«Опубликовать»** в админке обновляет только `data.json`. Чтобы заливать изменения HTML/CSS/JS, есть скрипт `tools/deploy-github.mjs` — он делает один коммит со всеми файлами сайта через GitHub API.

1. Создайте fine-grained token с правом **Contents: Read and write** на репозиторий сайта.
2. Сохраните токен в файл **вне проекта**:
   - `C:\Users\<вы>\.reshop-token` — только токен, без кавычек и пробелов.
3. Проверьте список файлов:

```powershell
node tools/deploy-github.mjs --dry-run
```

4. Опубликуйте:

```powershell
node tools/deploy-github.mjs
```

Скрипт берёт репозиторий `rshtlvv/reshot.github.io` и ветку `main` по умолчанию; их можно переопределить переменными `RESHOP_GITHUB_REPO` и `RESHOP_GITHUB_BRANCH`. Токен читается из `RESHOP_GITHUB_TOKEN` или из `%USERPROFILE%\.reshop-token`, в репозиторий не попадает. После работы токен можно отозвать.

## Как это работает

```
Админка → localStorage (черновик) → «Опубликовать» → GitHub Contents API → data.json в репозитории
                                                                         ↓
                                                          GitHub Pages пересобирает сайт
                                                                         ↓
                                              index.html / about.html читают data.json
```

- **data.json** — единственный источник правды для посетителей.
- Любые правки в админке сразу сохраняются в `localStorage` и сразу видны **в вашем браузере** — это режим предпросмотра.
- Пока вы не нажали «Опубликовать», другие люди видят старую версию сайта.
- «Опубликовать» записывает `data.json` в репозиторий. GitHub Pages обновляет сайт за 30–60 секунд.
- Загруженные через админку картинки коммитятся в `assets/items/` и подключаются относительной ссылкой.
- Если GitHub ещё не подключён, админка работает в **демо-режиме**: всё сохраняется только в браузере, а картинки — в виде data-URL внутри данных.

В шапке сайта у владельца появляется бейдж **«Черновик»**, если локальная версия отличается от опубликованной. У обычных посетителей его нет.

## Админ-панель

### Предметы
- Добавление, редактирование, удаление, изменение порядка стрелками.
- Поля: название, герой, слот, редкость, количество в наличии, цена и старая цена, статус (в наличии / зарезервирован / продано), бейдж «Хит», описание, отдельная ссылка Telegram.
- Цвет: необязательный HEX-код для конкретного предмета. Если не указан, берётся цвет редкости Dota 2.
- Изображение: загрузить файл (перетащить в область или выбрать) либо указать URL. При подключённом GitHub файл коммитится в `assets/items/`.
- Рекомендуемый формат картинки — 3:2, ширина от 900 px.

### Цвета и редкости
- Редкости используют цвета из Dota 2: `Arcana` — салатовый `#ADE55C`, `Immortal` — золотой `#E4AE39`, `Mythical` — фиолетовый `#8847FF`, `Legendary` — розово-малиновый `#D32CE6`, `Rare` — синий `#4B69FF`, `Ancient` — красный `#EB4B4B`, `Common` — `#B0C3D9`.
- Цвет редкости подставляется в бейдж, точку, свечение и название карточки. Поле **«Свой цвет (HEX)»** переопределяет его для одного предмета.
- В названии и описании можно красить отдельные слова: `{#ADE55C}слово{/}`. В редакторе есть кнопка **«Вставить цвет»** — она оборачивает выделенный фрагмент в этот синтаксис.
- Цвет применяется и в каталоге, и в модалке, и в списке админки. В поиске и Telegram-сообщении служебные теги автоматически отбрасываются.
- **Количество в наличии** выводится в карточке и в модалке; при нуле показывается «Нет в наличии».

### Обо мне
- Заголовок, лид, абзацы (разделяются пустой строкой), имя, роль, аватар.
- Цифры, шаги сделки и FAQ — списки с добавлением и удалением строк.
- Текст сохраняется автоматически с небольшой задержкой.

### Настройки
- **GitHub** — репозиторий, ветка, путь, токен, проверка подключения.
- **Магазин** — название, валюта, Telegram, ссылка Steam (кнопка Steam в футере ведёт на вашу trade-ссылку), подпись в футере.
- **Главная страница** — надзаголовок, заголовок (можно переносить строкой), текст, строка преимуществ и цифры. Слово в `*звёздочках*` становится акцентным.
- **Доступ** — смена пароля.
- **Данные** — экспорт JSON, импорт JSON, загрузка опубликованной версии с GitHub, сброс локальных правок.

## Пароль и доступ

- Пароль по умолчанию: `reshop`.
- Хранится в `localStorage` как SHA-256 (`reshop.pass.v1`), меняется в **Настройки → Доступ**.
- Если пароль забыт: откройте DevTools → Application → Local Storage → удалите ключ `reshop.pass.v1` и войдите с `reshop`.
- Пароль защищает только интерфейс от случайных глаз. Это статический сайт, поэтому настоящая защита — ваш GitHub-токен. Не публикуйте токен и не вставляйте его на чужих компьютерах.
- Рекомендуется fine-grained токен только на один репозиторий с правом **Contents: Read and write**.

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| Каталог пустой, в консоли 404 на `data.json` | Сайт опубликован из корня репозитория? `data.json` лежит рядом с `index.html`? |
| «Токен не принят» (401) | Токен истёк или у него нет права `Contents: Read and write`. |
| «Репозиторий не найден» (404) | Опечатка в owner/repo или у токена нет доступа к этому репозиторию. |
| Опубликовали, а сайт старый | Подождите минуту и обновите страницу с `Ctrl+F5`. GitHub Pages кэширует агрессивно. |
| Изменения видны только у вас | Так и должно быть: это черновик. Нажмите «Опубликовать». |
| Админка не входит | Открывайте через `http://localhost` или `https://`, не через `file://`. |
| Не загружается картинка | Файл больше 8 МБ или GitHub не подключён (тогда картинка сохранится в data-URL). |
